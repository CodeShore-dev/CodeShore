# Feature Map — CodeShore

**這份檔案只寫「功能叫什麼、怎麼操作、驗收看什麼」，不寫實作在哪個檔案。**

為什麼刻意不寫實作位置：程式碼變得比文件快。寫了實作位置，這份檔案就會過期，而 agent
照過期的位置去看會自己合理化。同一個理由讓 `orca-issue` 的「涉及檔案」只寫語意不寫行號
（見 `docs/pacer-log.md` 2026-09-30 那列）。

## 它解什麼問題

使用者在手機上給得出的全部就是「一張截圖加三個問號」。那種回報裡沒有選擇器、沒有元件名、
沒有檔案路徑——只有一句話。這份檔案讓那句話對得上一個確定的功能。

所以它是**雙向**的詞彙表：

- 使用者 → agent：「首頁那個技術的卡片」要能對上「首頁 / 技術組合」
- agent → 使用者：預審的 5 點要用**功能名**回報，不要用檔案路徑。手機上你讀得懂功能名

## 誰在什麼時候讀

- `orca-intake` / `orca-issue`：把一句話對應到功能，填 issue 的「現象」與「驗收條件」
- `orca-pr-review`：把發現的問題講成功能名
- **不進 `CLAUDE.md` 的 `@import`**，跟 `frontend-standards.md` 同一個待遇：由 skill 按需讀

## 怎麼維護

第一版手寫。開始過期時再寫一個 skill 自動產與更新——密度高到人手寫跟不上是預期的，
不是意外。每一列的驗收重點來自已經合併的 issue，新 issue 合併時順手補。

## 公開功能

### 首頁
- **使用者叫它**：首頁、首頁那個、第一頁
- **路徑**：`/`
- **怎麼操作**：進站就是。往下滑過四個區塊
- **區塊**：
  - Hero 輪播標語（10 秒切換，底下有分段進度條，每則文案一段）
  - 資料來源卡片（104 人力銀行 / Cake，整張卡片可點）
  - 熱門技術
  - 技術組合（同時顯示語言 / 框架 / 資料庫 / 函式庫四類，各取前幾個）
- **驗收重點**：
  - 輪播間隔 10 秒，不是 3 秒
  - 分段進度條要跟著輪播走：目前段倒數填滿、已播段維持填滿、未播段保持空白，否則 10 秒空白像卡住
  - 技術組合預設四類都顯示，不跟著「熱門技術」的分類切換而變
  - 來源卡片整張可點，不是只有右邊箭頭

### 職缺
- **使用者叫它**：職缺、職缺列表、工作列表
- **路徑**：`/jobs`
- **怎麼操作**：技術 / 薪資 / 公司篩選；切換「總數 / 喜歡 / 不喜歡」分頁；點一筆開詳情；分頁換頁
- **驗收重點**：
  - **篩選條件同步到 URL**，重整或分享連結後條件還在
  - 背景更新後詳情抽屜不會滾回最上面
  - 「喜歡 / 不喜歡」需要登入；訪客點了要顯示登入提示
  - 「總數」分頁不顯示子分類篩選列

### 職缺篩選追蹤
- **使用者叫它**：追蹤、我訂的條件、watchlist
- **路徑**：`/jobs/watchlist`
- **怎麼操作**：把一組篩選條件存起來追蹤
- **驗收重點**：訪客進來顯示登入提示，**不要跳轉到 `/login`**

### 公司
- **使用者叫它**：公司、公司列表
- **路徑**：`/companies`
- **怎麼操作**：搜尋公司名稱；搜尋技術；切換「排除公司 / 排除技術」；按技術類別篩（語言 / 框架 / 資料庫 / 函式庫 / 工具 / 其他）；「清除全部」；「查看職缺」連到職缺列表
- **驗收重點**：
  - 「查看職缺」是導航，不要順手把詳情展開
  - 排除與包含是兩種模式，切換時要看得出現在是哪種

### 技術
- **使用者叫它**：技術、技術頁、排行
- **路徑**：`/techs`（`/techs/combos` 會導到 `/techs?mode=combos`）
- **怎麼操作**：切「技術熱度 / 技術組合」兩個模式；切「高薪 · 年薪 / 高薪 · 月薪」；按分類篩或選「全部」
- **驗收重點**：模式與分類都在 URL 上，分享連結要回到同一個視圖

### 地圖
- **使用者叫它**：地圖、縣市地圖
- **路徑**：`/location-map`
- **怎麼操作**：預設縣市層級；點一個縣市開摘要 popup；按「進入鄉鎮市區分布」下鑽；popup 自己的「關閉」收起來
- **驗收重點**：
  - 平均薪資沒有值時顯示「—」，不要顯示 0 或空白
  - 縣市職缺數為 0 時，下鑽按鈕仍然要出現
  - 關閉 popup 不會把地圖的下鑽層級一起重設

### 方法論
- **使用者叫它**：方法論、你們怎麼算的
- **路徑**：`/methodology`
- **怎麼操作**：純閱讀頁
- **驗收重點**：手機上不要有水平滾動（長字串要能換行）

### 登入
- **使用者叫它**：登入
- **路徑**：`/login`、`/auth/callback`
- **怎麼操作**：第三方登入，回調後導回原本要去的頁
- **驗收重點**：已登入的人進 `/login` 要被導回首頁

### 關於
- **使用者叫它**：開源、法律、聯絡
- **路徑**：`/open-source`、`/legal`、`/contact`
- **怎麼操作**：純閱讀頁
- **驗收重點**：Footer 連得到，手機上不破版

### 導覽
- **使用者叫它**：上面那排、選單、底下那排
- **位置**：桌機頂部導覽列、手機底部導覽列、Footer
- **怎麼操作**：主要五項固定顯示（首頁 / 職缺 / 公司 / 技術 / 地圖）；管理員另有「更多」下拉
- **驗收重點**：
  - 在 `/jobs?tab=...` 這類子視圖時，「職缺」不算 active
  - 非管理員看不到「更多」，而且不是看到空的下拉

### 找不到頁面
- **路徑**：任何未匹配的路徑
- **驗收重點**：顯示 404 頁面，不要出現空白或框架錯誤畫面

## 手機回報怎麼用這份檔案

手機送進來的 intake issue 只有三樣：**網址**、**一句話**、**`window.innerWidth`**。
對應步驟：

1. 用網址對上路徑，查到是哪個功能
2. 用那句話對上該功能的某個區塊或操作
3. 用該功能的「驗收重點」當 issue 的驗收條件起點
4. **RWD 問題看回報的 `innerWidth` 配 Tailwind 的斷點前綴**（`md:`、`lg:`），
   不必真的渲染在那個寬度。斷點寫在 class 名字裡，是宣告式的
